## 所属小组（步骤 1）

### 目标

不再一次性列出全部小组 chip。用户以**会话输入框**输入小组名称做模糊匹配；匹配后二次确认或 chip 点选。进场与零命中时提供**随机 4 个**快捷 chip。

### 子状态

仅在 `key === 'group'` 时有效：

| 状态 | 类型 | 含义 |
|------|------|------|
| `groupPhase` | `'pick' \| 'confirm'` | 搜选 / 唯一命中二次确认 |
| `groupCandidates` | `Group[]` | 当前展示的 chip（初始/零命中/点「否」= 随机最多 4；多命中 = 全部匹配结果） |
| `pendingGroup` | `Group \| null` | 唯一命中待确认的小组 |

### 流程

```
进场（groupPhase = pick）
  AI：「先选一个所属小组吧～」
  UI：随机最多 4 个 chip + 会话输入（placeholder：输入小组名称）

  ├─ 点快捷 / 候选 chip → 直接 commit（用户气泡 = 小组名）→ 步骤 2
  │
  └─ 会话发送 → 对 store.groups.name 模糊匹配（trim；名称 includes 查询串）
       ├─ 0 命中 → AI：「没找到相关小组，换个名字试试～」
       │            + 新随机最多 4 chip；仍 pick
       ├─ 1 命中 → groupPhase = confirm；pendingGroup = 该组
       │            AI：「是「{name}」吗？」
       │            chip：是 / 否
       │            是 → commit → 步骤 2
       │            否 → pick；pendingGroup = null
       │                 AI：「好的，再输入小组名称，或点下面快捷选～」
       │                 + 新随机最多 4 chip
       └─ N 命中 → AI：「找到这几个，选一个吧～」
                    + 全部候选 chip（原型小组少，不截断）
                    点选 → commit → 步骤 2
```

confirm 阶段若用户再次在输入框发送：视为**新搜索**（回 pick 流程重匹配），不强制禁用输入。

### 匹配规则

- 数据源：`store.groups`（与现网一致，不另限「我管理的」）
- 规则：`name` 包含查询串（去首尾空格）；原型不做拼音 / 编辑距离
- 空输入：不发送
- `groups.length === 0`：AI「暂无可用小组」，禁用输入（原型几乎不触发）
- 随机 4：洗牌后取 `min(4, length)`；不足 4 则全出

### 实现落点

- 文件：`site/assets/191074b9-….js` 内 `ActAiGuide`
- 辅助：`fuzzyMatchGroups(groups, q)`、`pickRandomGroups(groups, n)`
- `sendText`：补 `key === 'group'` 分支（当前缺失）
- 去掉进场 `groups.map` 全量 chip

### 手测（用全量数据，不限示例词）

用例须覆盖 `DB.groups` **全部**小组名称及其任意有效子串，不固定「夜跑 / 球 / xyz」：

1. **进场快捷**：见最多 4 个随机 chip；点任一 → 进入活动类型步；用户气泡为该组名  
2. **唯一命中**：对每个小组，用全名或能唯一命中的子串发送 → 出现「是「{name}」吗？」+ 是/否；「是」进类型步；「否」回 pick 并刷新随机 4  
3. **多命中**：用能命中 ≥2 个组的子串发送 → AI 提示 + **全部**候选 chip；点选正确 commit  
4. **零命中**：用任一不匹配任何组名的串 → 提示换名字 + 新随机最多 4 chip；可继续输入  
5. **confirm 再搜**：唯一命中进入 confirm 后，再输入另一有效名称/子串 → 按新搜索结果走 0/1/N  
6. **回归**：选定小组后，类型 → 标题… 后续步骤与发布路径不变
